# Antumi 使用指南

这里提供配置说明和常用功能查阅。首次使用时，宠物会检查 Agent 是否安装、能否使用，并询问是否配置任务来源。需要重新检查时，打开左下角 **帮助 → 检查使用环境**。

## Agent 安装与登录

打开 [**设置 → 外部智能体**](antumi:settings/agents)，查看安装、启用和可用状态。Agent 可通过自己的账号或兼容的模型服务商使用；具体需求以环境检查提示为准。

![设置 → 外部智能体：装好并登录的 Agent 标着已就绪](assets/guide/agents-ready.png)

- 需要使用 Agent 自己的账号：在终端运行那一行给出的登录命令，再点 **重新检测**。
- 列在 **可安装** 里：点 **在终端安装**，或复制安装命令自己跑，装完点 **重新检测**。
- 使用模型服务商：按下节配置兼容的服务商；已在 Agent 自己的配置中接入的，可按环境检查提示确认。

### 项目和 Agent 都在 WSL 里（Windows）

平时在 WSL 里干活、Agent 也只装在发行版里的话，让 Antumi 的后端也在那里运行：打开 **设置 → 后端位置**（只在 Windows 的安装版里有），把运行位置选成那个发行版，Antumi 会重启。之后选项目时看到的是发行版里的目录，用的是发行版里的 git 和 Agent。

- 发行版要是 WSL 2、x64，里面装好 Node 24 以上，并且是登录 shell 默认的那个版本。不满足时设置页会说缺什么、怎么补，这次先用本机的后端。
- 两边的任务、会话和设置各是一份，互不相通；切回本机时，原来的都还在。
- 后端在 WSL 里时暂时没有：手机在局域网里直连，以及保持电脑唤醒。

## 模型服务商

**已有账号或服务商配置可以直接沿用。** 仅有本机配置时，桌面端会话输入框自动沿用它，省略服务商下拉框。添加适用于当前 Agent 的服务商后，可在输入框的 **服务商 → 本机配置** 继续使用 Agent 现有的账号或服务商，包括 CC Switch 为 Claude Code / Codex 配好的中转 API。设置 → 外部智能体 会区分「已就绪 · 登录账号」和「已就绪 · 本机服务商配置」；旧版后端仍显示通用就绪状态。切换 CC Switch 后，新启动的 Agent 进程读取新配置，正在运行的进程需要重新启动。

想在 Antumi 单独管理编程套餐或 API，再按下面的步骤添加服务商。

**从 CC Switch 导入**：在 **设置 → 服务商** 点 **从 CC Switch 导入**，读取列表、勾选需要的项，再点 **导入所选服务商**。支持 Claude Code / Codex 的 API 服务商，包括未启用项；读取的是后端所在电脑用户目录下的 `.cc-switch/cc-switch.db`，也兼容旧版 `config.json`，改过数据位置时填写实际目录。预览不显示 Key，导入后 Key 存在 Antumi 的凭据文件里；已有同名、同接口、同 Key 的配置会跳过，不覆盖任何服务商，也不修改 CC Switch。

导入是一次性复制，之后可在 Antumi 独立选择服务商；CC Switch 后续改动不会自动同步。没有保存模型名的条目会在导入时尝试获取 `/models`，失败只影响该项，结果页会标明；可在 CC Switch 补充模型配置后重试。导入不调用模型或自动执行连接测试，「标题、翻译、提交说明」默认关闭。官方订阅、OAuth 托管或暂不兼容的条目会注明原因，仍可通过「本机配置」使用。

![设置 → 服务商 → 添加服务商：选套餐，填 API Key](assets/guide/provider.png)

在 [**设置 → 服务商**](antumi:settings/model-providers) 点 **添加服务商**：选套餐、粘贴 API Key、勾选给哪些 Agent 用，点 **保存并测试**，每项都是 ✓ 就能用。Cursor 用不了服务商。

新建会话时在输入框的 **服务商** 里选它，按服务商计费，不占官方额度；会话开始后不能再换。

**本机代理（CLIProxyAPI 等）**：选 **CLIProxyAPI**，地址按默认端口 8317 填好，Key 填它配置里 `access.api-keys` 的一个，再点 **从接口获取模型**。其他代理选 **自定义**：Claude Code 要填 Anthropic 协议地址，Codex 要填 Responses 地址，OpenCode 填哪种都行；接口没列出上下文大小的，在模型表格的 **上下文**、**最大输出** 两列按实际上限填；能看图的模型勾上 **支持图片**。

通过代理使用 Claude、Gemini 等订阅账号可能违反其服务条款并导致封号，长时间无人值守、多个会话同时跑时更容易触发。CLIProxyAPI 默认不让标题、翻译这类 Antumi 自己发的小请求走它（**标题、翻译、提交说明** 一项）；代理要靠请求头认客户端的，在 **额外请求头** 里填。

## 多个账号

**可选，** Claude Code、Codex、Antigravity 和 CodeBuddy 支持。

![设置 → 账号：额度用完自动换号，以及添加账号](assets/guide/accounts.png)

在 [**设置 → 账号**](antumi:settings/accounts) 点 **添加 Claude Code 账号**（或 Codex、Antigravity），再点 **添加并登录**，在下方终端登录后点 **设为当前**。额度用完时默认自动换到下一个账号，会话接着跑。

Antigravity 在浏览器中授权 Google 账号，终端显示进度。可分别查看各账号额度；服务把额度不足作为普通回复时，当轮不会自动重试。

## 任务来源

**可选，** 要从 GitHub、Jira、Linear、禅道导入任务时才要。

![设置 → 插件 → 推荐插件](assets/guide/plugins.png)

1. 在 [**设置 → 插件**](antumi:settings/plugins) 点 **安装插件**。
2. 打开 **设置 → 集成 → 来源名称**，填站点和筛选条件，点 **登录** 填 Token，打开 **同步到收件箱**。
3. 在侧栏 **收件箱** 点 **立即同步**，选一条点 **导入任务**。

| 来源 | 需要准备 |
|---|---|
| GitHub | Personal access token、搜索条件（只看 Bug 可加 `label:bug`） |
| Jira | 站点、登录邮箱、API token、JQL |
| Linear | 个人 API Key |
| 禅道 | RESTful API v1 地址（如 `https://zentao.company.com/zentao/api.php/v1`）、Token、产品 ID |

推荐里没有的平台，可以在 **从其他位置安装** 填 GitHub 仓库或选本地 ZIP；想自己写一个，见 [插件开发指南](https://github.com/flyhero/antumi/blob/main/docs/PLUGINS.md)。

## 在手机上使用

**可选，** 目前只有 Android 版。离开电脑时，在手机上看会话、回答确认、发消息让 Agent 接着做。Agent 仍在电脑上运行，手机断开不影响它们。

1. 在 [GitHub Releases](https://github.com/flyhero/antumi/releases) 下载 `Antumi-…-android-arm64-v8a.apk` 并安装，绝大多数手机都用这个；很老的 32 位手机装不上时，改下 `Antumi-…-android-armeabi-v7a.apk`。第一次要允许「安装未知来源应用」；手机提示有风险时，确认来源后选继续安装。
2. 在 [**设置 → 手机**](antumi:settings/mobile) 打开 **允许手机连接**，点 **添加手机**。
3. 手机上点 **添加电脑**，扫描电脑上的二维码。扫不了时，在电脑上点 **复制配对链接**，发到手机上点开，或粘贴到 App 里。
4. 核对手机和电脑上的 6 位确认码，一致后在电脑上选：
   - **允许查看**：只能看会话和任务；
   - **允许查看和操作**：能发消息和图片、回答确认、新建会话，也能放宽权限，等于把会话的控制权交给这台手机。

手机和电脑要在同一个 Wi‑Fi 下，电脑开着且没有休眠（可以点状态栏的咖啡杯，打开 **保持唤醒**）。手机丢了，在 **设置 → 手机** 的设备列表里点 **撤销**；手机端的 **设置** 里还可以打开「打开时验证指纹或面容」。

### 在外面用：配合 Tailscale

不在同一个 Wi‑Fi 时，手机通过 [Tailscale](https://tailscale.com) 连回电脑。Antumi 不经过任何服务器，Tailscale 只是让两台设备像在同一个网络里。

1. 电脑和手机都装 Tailscale，登录同一个账号。
2. 在电脑的 **设置 → 手机** 里看「手机会尝试这些地址」，里面出现一个以 `.ts.net` 结尾的名字，就说明 Antumi 认出了 Tailscale。
3. 照常扫码配对。已经配对过的手机不用重扫：它下次连上电脑时会自动记下这个名字。
4. 出门后手机上保持 Tailscale 开着。手机先试局域网地址，连不上会很快改走 Tailscale。

连不上时检查：电脑上的 Tailscale 和 Antumi 都在运行；Tailscale 的 MagicDNS 开着（默认开）；改过 Tailscale 访问控制的话，要允许手机访问电脑的 7820 端口（或你在 **设置 → 手机** 里改过的端口）。Android 同一时间只能开一个 VPN，开着别的 VPN 时 Tailscale 会被关掉。

### 在外面用：经自己服务器上的 Antumi 中转

有一台带公网 IP 的 Linux 服务器时，可以在上面装一个 Antumi 中转：电脑一直连着它，手机在外面经它连回电脑。手机上不用装别的 App，走普通的 TCP，也不占手机的 VPN；内容照旧端到端加密，中转只转发它看不懂的数据。

1. 在 **设置 → 手机** 的 **连接方式** 里，点「自己的服务器（Antumi 中转）」的 **设置**，点 **复制安装脚本**。
2. 用 root 登录服务器粘贴执行（Debian、Ubuntu、CentOS、Alibaba Cloud Linux 等都行）。服务器上已有 Node.js 14 以上就直接用它，没有会自动安装；装好后中转开机自动启动。再到云控制台的防火墙或安全组放行 TCP 7830。
3. 回到设置页，在第 2 步填服务器的公网 IP 或域名，保存。第 3 步显示「已连上中转」就好了。
4. 新配对的手机扫码就会用上中转；已经配对的手机在家里连上电脑一次就会记下。

在 3Mbps 的云服务器上，经中转传一张 2MB 的图片大约 5 到 7 秒。

没有服务器的话，可以加作者微信 `Wang_hero2014`（注明 Antumi）申请用作者的中转：拿到地址后跳过第 1、2 步的安装，直接在第 3 步填上。作者的中转由大家共用，带宽有限，不保证一直可用。

### 在外面用：经自己的服务器（WireGuard）

有一台带公网 IP 的 Linux 服务器（云服务器就行，3Mbps 带宽够用）时，可以让它用 [WireGuard](https://www.wireguard.com) 在手机和电脑之间转发。手机和电脑之间本来就端到端加密，服务器只转发它看不懂的数据。电脑上不用装 VPN，也不要管理员权限：Antumi 自己运行 [wireproxy](https://github.com/windtf/wireproxy)，第一次用时从 GitHub 下载（约 4MB）。macOS、Windows、Linux 做法一样。

1. 在 **设置 → 手机** 的 **连接方式** 里，点「自己的服务器（WireGuard）」的 **设置**，填服务器的公网 IP 或域名（UDP 端口默认 51820）；云服务器有限速的，在带宽一格填它的 Mbps 数（比如 3），电脑发到手机会快好几倍。点 **生成配置**。
2. 点 **复制服务器脚本**，用 root 登录服务器粘贴执行（Debian、Ubuntu、CentOS、Alibaba Cloud Linux 等都行），它会装好 WireGuard 并设成开机自动启动。再到云控制台的防火墙或安全组放行这个 UDP 端口。
3. 回到设置页，第 2 步显示「已连上服务器」，电脑这边就通了。
4. 手机扫设置页左边的码安装 WireGuard（没有 Google Play 的手机选「Download APK File」）。在 WireGuard 里点 **+** → **扫描二维码**，扫设置页上点 **显示配置码** 出来的码，打开开关。只有 10.77.0.x 这一段走服务器，可以一直开着，不影响手机上网。

已经配对过的手机不用重新扫 Antumi 的码，它下次连上电脑时会记下中转地址。

连不上时检查：设置页第 2 步的提示；服务器上 `wg show wg-antumi` 能不能看到电脑和手机最近的握手。Android 同一时间只能开一个 VPN，和 Tailscale 二选一。用别的隧道或端口转发时，把手机在那边连的地址填进 **其他地址**。

### App 关着时收提醒：ntfy

1. 手机上装 [ntfy](https://ntfy.sh) App，订阅一个只有你知道的主题，例如 `antumi-` 加一串随机字符。
2. 在电脑的 **设置 → 手机 → 推送地址** 填 `https://ntfy.sh/你的主题`，保存。

有会话在等你确认、本轮结束或 Agent 意外退出时，ntfy 会推一句提醒，不含会话标题和内容。ntfy.sh 是公共服务器，主题名别太好猜；也可以填自建 ntfy 的地址。

## 让同事在 Slack、飞书或钉钉上提问

把一个智能体接到 Slack 上，同事在频道里 @ 它，它读你选中的项目来回答：某个功能在哪实现的、这个报错是什么原因。它不改代码，也碰不到这台电脑上别的东西。

1. 在 **智能体** 页新建一个智能体，最上面选 **接到聊天平台**，在「工作指令」里写清楚它答什么、答多长，保存。这种智能体只在聊天平台上回答，没有技能、MCP 要配，也不出现在你自己的会话和委派里。
2. 保存后页面下面出现 **聊天平台**，点 **添加 Slack**，照着五步做：
   - 打开 Slack 的应用页面，选 **Paste a manifest**，粘贴 Antumi 给的清单，创建后安装到工作区。
   - 填两个 token：App-Level Token（Basic Information → App-Level Tokens，权限选 `connections:write`）和 Bot User OAuth Token（OAuth & Permissions）。
   - 选它可以读的项目。只能读 Git 仓库里没被 `.gitignore` 忽略的文件，`.env`、密钥这类文件不提供。
   - 填可以提问的成员 ID 和频道 ID。没填的人问了只会收到「没有权限」。
   - 设每人每天、每天总共能问几次。
3. 保存后状态变成「已连接」，在频道里 `/invite` 这个应用，就可以 @ 它了。它会先在消息上加一个 👀，答案回在这条消息下面；接着问要再 @ 一次。可以带截图，其他文件它不看。

要知道的几点：

- 没给智能体选模型服务商时，同事的提问用的是你 Claude Code 当前账号的额度。
- 电脑关机或睡眠时收不到提问，平台也不会补发。
- 一个串里换了人提问，它不记得前一个人问过什么：每个人各有各的上下文。
- 谁问了什么、它读了哪些文件、答了什么，在同一处的 **提问记录** 里都能看。

### 接飞书

步骤一样，点 **添加 飞书**。不同的是建应用和填 ID：

- 在飞书开发者后台建一个「企业自建应用」，加上「机器人」能力；到「权限管理」→「批量导入/导出权限」，粘贴 Antumi 给的权限清单，再发布一个版本。
- 填「凭证与基础信息」里的 App ID 和 App Secret，保存。状态变成「已连接」后，回到后台的「事件与回调」，订阅方式选「使用长连接接收事件」，添加事件「接收消息」，再发布一个版本。飞书要先连上才让保存长连接，所以先在 Antumi 里保存。
- 飞书里看不到成员 ID 和群 ID。先把机器人拉进群，让同事 @ 它问一句：还没开通的人会收到一条回复，里面有自己的 ID（`ou_` 开头）和群 ID（`oc_` 开头），填进白名单就行。
- 群里的回答发成话题，在话题里 @ 它接着问。

用的是 Lark（飞书国际版）就点 **添加 Lark**，步骤和飞书完全一样，只是在 Lark 开发者后台（open.larksuite.com）建应用。

### 接钉钉

步骤一样，点 **添加 钉钉**。不同的是：

- 在钉钉开发者后台的「应用开发 → 企业内部应用」里建一个应用，在「添加应用能力」里加上「机器人」，消息接收模式选「Stream 模式」，发布机器人。到「权限管理」申请「企业内机器人发送消息权限」（下载截图、回答慢时都要用到），再发布一个版本。
- 填「凭证与基础信息」里的 Client ID 和 Client Secret，保存，等状态变成「已连接」。
- 成员 ID 是通讯录里的 userId，管理后台的成员详情里能看到；群 ID（`cid` 开头）看不到，同样让同事先 @ 机器人问一句，从那条「没有权限」的回复里拿。
- 钉钉的机器人不能在话题里回答，也不能加 👀：回答是群里的一条新消息，会 @ 提问的人；每次 @ 都是一个新问题，它不记得上一问。私聊里它记得前面聊过什么。

## 常用功能

遇到相关场景时，可以在这里查阅。

### 无缝移交

![输入框左下角的 Agent 菜单](assets/guide/handoff.png)

额度用完了，或者想换个 Agent 接着做：点输入框左下角的 Agent 名称，换一个，写句补充说明，点 **移交**。新 Agent 会带着聊天记录，在同一个目录里接着做。

### 跨会话引用

需要参考之前讨论的方案时，在输入框输入 `@`，切到 **会话**，按标题、项目或 Agent 查找并选择，再写下要做的事。当前 Agent 会按需读取被引用的历史记录，继续在当前目录工作；发送后的会话标题可点击打开原对话。

会话分类需要在 [设置 → 权限](antumi:settings/permissions) 中开启 **让 Agent 读你在 Antumi 里的记录**；开启后从 Agent 下次启动起提供读取工具，关闭后立即停止读取。移交用于换 Agent 接手当前工作，跨会话引用用于补充参考资料。

### 预约：额度恢复后或到点再发

![点时钟按钮后弹出的「预约发送」](assets/guide/schedule.png)

1. 在输入框里写好消息。
2. 点输入框右下角的 **时钟** 按钮。
3. 选 **额度恢复后**，或 **指定时间**。
4. 点 **预约**。

| 还能预约 | 在哪里 |
|---|---|
| 任务 | 任务工具栏上的时钟按钮 |
| 计划批准 | 计划卡片上的 **预约批准** |
| 查看、改时间、取消 | 状态栏的「N 个预约」，或总览的「接下来」 |

到点后，Agent 按弹窗里写的模式无人值守运行，点 **在设置里改** 可以换。电脑睡着时预约不会运行，可以打开状态栏咖啡图标的「保持电脑唤醒」。

同一个 Agent 的预约按列表顺序一条跑完再开下一条，等待中的会写明排在哪一条后面。额度用了不到六成、又不是刚恢复的半小时内，就不再等，每分钟开始一条。你在预约开始的会话里自己接着聊，后面的预约不必等你聊完。

预约批准之后，计划卡片收起，输入框上方只留这条预约；想现在就处理，点它旁边的 **现在处理**，计划卡片会回来。到点前你已经在别处处理了这个计划，这条预约会自动取消，不会再让 Agent 按计划开工一次。

### 分屏：两个会话并排

![会话右键菜单里的「在右侧分屏打开」](assets/guide/split.png)

| 操作 | 方法 |
|---|---|
| 打开分屏 | 右键另一个会话 → **在右侧分屏打开**；或按住 ⌘ 点它；或把它拖到聊天区 |
| 切换焦点 | ⌘1 左侧，⌘2 右侧 |
| 调整宽度 | 拖动中间的分隔线 |
| 收起 / 恢复 | ⌘\ |

两侧可以分别输入、看进度、处理批准。

### 小助手与翻译

![选中文字后的右键菜单](assets/guide/helper.png)

选中回复里的一段，右键：

- **交给小助手**：在右侧打开，用轻量模型和独立上下文解释、追问，不占主会话。
- **翻译**：只翻译选中的这段。回复不是你的语言时，回复下方也会出现 **翻译** 按钮，可以翻整条。

![设置里的「翻译」](assets/guide/translate.png)

| 设置项 | 位置 |
|---|---|
| 翻译成哪种语言、是否自动翻译、翻译用的模型 | [**设置 → 会话**](antumi:settings/conversation) |
