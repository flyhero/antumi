# Antumi 快捷键重新规划

状态：分批实施，其余键位仍为设计提案。调研日期：2026-10-29。

实施进度：已将现有 23 项应用操作统一接入快捷键设置，按应用、任务、会话、聊天、文件、面板和表单分组，支持搜索、录入、按生效区域检查冲突、禁用、恢复默认、按平台保存，以及面板在内置浏览器中的转发。侧栏、分屏、聊天菜单、输入提示和文件操作显示当前绑定；复制粘贴等原生操作列为参考。原先三个面板的自定义设置继续保留。下文尚未实现的新增入口仍是规划，不代表已交付。

## 结论

以「创建任务 → 找到正在做的事 → 回复或处理等待 → 查看改动」组织快捷键。保留已经形成习惯的键位，补齐跨任务、会话和群聊的入口，并统一聊天、编辑器、终端和内置浏览器的响应规则。

核心决定：

- `⌘N` 继续新建任务；`⌘⇧N` 新建会话，符合 Antumi 的任务优先定位。
- `⌘K` 搜索并切换会话、任务、智能体和文件，原来的 `⌘P` 转到文件并入其中；`⌘⇧P` 查找并执行命令。
- `⌘1/2` 继续聚焦左右分屏。会话的分组、折叠和排序会变化，不给列表位置分配数字键。
- 为「回到输入框」「跳到下一条待处理」「聚焦当前请求」提供直接入口，缩短管理多个 Agent 的操作路径。
- 所有按键都明确作用域；一个按键只执行一次，隐藏窗格和后台会话没有响应权。

## 现状与缺口

| 现有行为 | 评估 / 缺口 |
| --- | --- |
| `⌘N` 完整新建任务；看板空白焦点下 `N` 快速记任务 | 保留。两种入口分别服务完整配置和连续录入 |
| `⌘P` 转到文件；`⌘⇧E` 文件面板；`Ctrl+反引号` 终端 | 转到文件并入 `⌘K`，一个入口更快；面板键保留，与开发工具的习惯一致 |
| `⌘F` 当前聊天查找；`⌘S` 保存文件 | 保留局部作用域，扩展时不抢其他内容区的查找和保存 |
| `⌘1/2` 聚焦分屏；`⌘\` 收起或恢复上一对分屏 | 保留。并不是根据当前会话复制出一个新窗格 |
| `Enter` 发送或排队；`⌘Enter` 即时补充；`⌘⇧Enter` 发到同配置新会话 | 保留能力差异，统一帮助文案；输入框根据 Agent 实际能力显示可用动作 |
| `Esc` 关闭菜单、退出查找、中断输入框对应回合、返回看板；部分请求卡片还会停止或跳过 | 需要统一消费顺序；退出请求焦点不应自动提交拒绝或跳过 |
| 新建会话、同配置新建、交接、检查器等主要靠按钮和菜单 | 高频动作补直接入口；其余通过命令面板访问 |
| 会话列表已有标题、项目和正文搜索，但无统一跨对象键盘入口 | `⌘K` 提供统一切换入口；全文查询保持明确的范围 |
| 浏览器页面获得焦点后，renderer 收不到按键 | main 需要转发明确保留给应用的按键，业务动作仍由 renderer 执行 |

代码中还存在一个确定的不一致：renderer 用物理 `Ctrl+Shift+反引号` 切换浏览器；浏览器 host 先检查平台主修饰键，因此 macOS 页面内实际检查的是 `⌘+Shift+反引号`。同一功能会因焦点位置而使用不同键位，应在统一注册表时修正。

现有入口见 [App.tsx](../packages/desktop/src/renderer/src/App.tsx)、[ChatComposer.tsx](../packages/desktop/src/renderer/src/components/ChatComposer.tsx)、[chat-send-ways.ts](../packages/desktop/src/renderer/src/chat-send-ways.ts)、[ChatFind.tsx](../packages/desktop/src/renderer/src/components/ChatFind.tsx)、[browser-host.ts](../packages/desktop/src/main/browser/browser-host.ts)。

## 默认键位

macOS 使用 `⌘`，Windows / Linux 默认使用 `Ctrl`；`⇧` 表示 Shift。明确写出的 `Ctrl` 在 macOS 上也仍然是 Control。终端与网页的例外见后文，不能只做机械替换。

「应用」表示 Antumi 自己的界面；模态对话框打开时，导航和创建动作暂停。命令面板、弹窗和设置都应保留原页面草稿。

### 创建、查找和切换

| 动作 | macOS | Windows / Linux | 作用域与语义 | 阶段 |
| --- | --- | --- | --- | --- |
| 新建任务 | `⌘N` | `Ctrl+N` | 应用；打开完整任务对话框 | P0，保留 |

| 新建会话 | `⌘⇧N` | `Ctrl+Shift+N` | 应用；打开空白会话输入页，沿用新建入口现有的默认值规则 | P0，新增 |
| 快速切换 | `⌘K` | `Ctrl+K` | 应用；按名称、项目和任务编号找会话、任务、智能体和当前项目的文件，会话也搜消息正文；不输入时列出最近的会话和任务 | P0，已实现（群聊待加） |
| 命令面板 | `⌘⇧P` | `Ctrl+Shift+P` | 应用及明确保留的嵌入内容入口 | P0，新增 |
| 最近访问的工作项 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | 同左 | 应用；在任务、会话、群聊之间按最近访问顺序切换 | P1，新增 |
| 下一条待处理 | `⌘⇧U` | `Ctrl+Shift+Y` | 应用；按现有待处理优先级定位，定位不提交回应 | P1，新增 |
| 设置 | `⌘,` | `Ctrl+,` | 应用 | P0，保留 |
| 快捷键速查 | `⌘/` | `Ctrl+/` | 应用非编辑区；编辑器内保持注释等局部语义 | P0，新增 |

快速切换与命令面板共用一个浮层和结果行组件：`⌘K` 进入对象模式，`⌘⇧P` 进入以 `>` 标识的命令模式。默认对象结果优先最近访问；显示类型、项目、Agent 和等待状态。任务自己的聊天只作为任务返回，避免同一件事出现两行；群聊成员同理。

第一版对象搜索覆盖标题、项目和任务编号，不承诺新增跨对象全文检索。现有会话正文搜索可以保留为明确的「搜索会话内容」命令。命令面板里的低频入口包括总览、任务看板、收件箱、定时、团队、Worktree 管理、同配置新建、交接、置顶、归档等。

快速切换中的 `↑/↓` 选择，`Enter` 打开，`Esc` 关闭并还原焦点；只有结果可分屏时才显示 `⌘Enter` / `Ctrl+Enter` 在另一列打开。切换时保留两边草稿；如果目标已经在另一列，直接聚焦该列。

最近访问按“用户实际打开”记录，不按 Agent 的更新时间。按住 Ctrl 可查看并循环选择，松开提交，Esc 取消；列表在本次选择期间固定。内置浏览器和终端内的 `Ctrl+Tab` 保留给本地标签或 TUI，跨内容切换使用命令面板。

待处理导航复用 [attention.ts](../packages/desktop/src/renderer/src/attention.ts) 的 `actionableItems`：批准 / 问答、异常退出、待验收、待回复，组内沿用现有排序；不另建状态判断。连续按键在当前待处理队列中前进，队列变化时按稳定 ID 续接；没有下一项时回到队首，没有任何项时提示「没有待处理事项」。未读完成消息不是待处理项，作为单独命令查询。这里的「待处理」也不等于收件箱里的外部事项。

| 换行 | `Shift+Enter` | 同左 | 输入框 | P0，保留 |

| 下一个 / 上一个匹配 | `⌘G` / `⌘⇧G` | `F3` / `Shift+F3` | 已打开的查找；保留现有聊天其他有效别名 | P0，保留 |

Windows / Linux 回到输入框使用 `Ctrl+Shift+J`，避免把终端的 `Ctrl+J` 换行变成应用导航。快捷键提示从同一动作定义读取，各平台显示实际按键。

Windows / Linux 的待处理导航使用 `Ctrl+Shift+Y`，避开部分 Linux 输入环境以 `Ctrl+Shift+U` 开始 Unicode 输入的习惯；请求聚焦使用 A，避开 `Ctrl+Shift+I` 的常见开发者工具入口。回到聊天的 `Ctrl+Shift+J` 则明确作为 Antumi 保留键，不接管独立 DevTools 窗口。这些是平台差异，不是把 ⌘ 直接替换成 Ctrl。参见 [GNOME 特殊字符输入](https://help.gnome.org/gnome-help/tips-specialchars.html)、[Chrome 开发者工具快捷键](https://developer.chrome.com/docs/devtools/open)。

Enter 继续默认发送。`Mod+Enter` 在空闲时增加发送行为，运行中继续表示即时补充；现有代码在空闲时会因为不可 steer 而不发送，这里是有意调整。候选菜单和中文输入法优先于发送；菜单打开时 Enter 只选中候选，输入法确认时不发送。运行中不支持即时补充时保留草稿并说明原因，不把它静默改成排队。

请求卡片保留 `↑/↓` 和 `1–9` 选择，`Enter` 提交；文本输入区里的数字只输入文本。聚焦请求必须先展示请求内容并把焦点放入卡片，不应由跳转键直接批准。继续使用实际 Agent 提供的选项和现有权限规则。

检查器选择 `⌘⇧L` 而非 `⌘L`，将浏览器地址栏的习惯保留下来。端口面板、最大化面板、同配置新建和交接先通过命令面板访问，不额外占用默认键。

## Esc 的统一规则

一次 Esc 只执行最内层正在处理的动作，并消费这次事件：

1. 中文输入法正在组合文字时，由输入法处理。
2. 候选菜单、右键菜单、命令面板、对话框或查找栏打开时，只关闭当前最上层；恢复打开它的焦点。
3. 输入框有待采用的建议时，只隐藏建议。
4. 请求卡片获得焦点时，退出卡片回到聊天输入框，保留当前选择；不拒绝、不跳过、不执行计划。
5. 当前活动聊天的输入框获得焦点、Agent 运行中且没有以上内容时，保留 Esc 中断当前回合的习惯。
6. 任务详情的非输入区，无更内层处理者时返回看板；其他普通页面不做额外动作。

内置浏览器页面中的 Esc 交给网页，用于退出网页菜单、编辑状态等；取消当前「Esc 返回应用、Shift+Esc 送给网页」的反向习惯。回到聊天改用 `⌘J` / `Ctrl+Shift+J`，也可用 `F6` 切换主要区域。终端的 Esc 始终交给 shell / Vim / TUI。

## 焦点与冲突规则

优先级：输入法 → 顶层模态 / 菜单 → 当前控件 → 当前内容区 → 应用保留动作。应用明确保留的跨内容入口可以在局部控件处理前识别，但模态和输入法规则仍优先。

| 场景 | 应用可以接管 | 必须保留给当前内容 |
| --- | --- | --- |
| 普通聊天输入框 | 创建、切换、命令面板、回到输入框等明确的应用动作 | 选区、剪贴板、撤销、光标、输入法；有候选菜单时的 Enter / Tab |
| 文件编辑器 | 命令面板、新建任务 / 会话和明确不冲突的面板入口 | 保存、查找、注释、格式、多选等编辑器操作 |
| macOS 终端 | 默认仅命令面板、新建任务 / 会话、回到聊天、终端 / 浏览器开关、F6 | 全部物理 Ctrl 序列、Esc 和 TUI 操作；上列物理 Ctrl 面板开关是明确例外 |
| Windows / Linux 终端 | 默认仅 `Ctrl+Shift+P`、`Ctrl+Shift+N`、`Ctrl+Shift+J`、两个面板开关、F6 | `Ctrl+C/D/Z/K/N/P/B/J/L/R/U/W`、Tab、Esc、`Ctrl+Tab` 和其他未保留按键 |
| 内置浏览器 | 两平台的命令面板、新建任务 / 会话、回到聊天、两个面板开关、F6 | Esc、`Mod+L`、`Mod+F`、`Mod+R`、`Mod+T/W`、`Ctrl+Tab`，以及网页输入区的编辑按键 |
| 请求卡片 | 聚焦区域与必要导航 | 选择、输入和提交由当前卡片处理，后台卡片没有提交权 |

这里的浏览器键位是目标分工，并不意味着当前 Antumi 已经实现浏览器查找、地址栏聚焦和标签快捷键；相应功能列入 P1。第一版只转发保留入口，其余不拦截，缺少的浏览器宿主动作仍可用现有按钮。

实施约束：

- 检查 `defaultPrevented`、`isComposing`、长按重复和 AltGraph，按动作决定是否允许重复。创建、发送、审批和切换面板不因长按重复执行。
- 修饰键精确匹配；`⌘N` 不能误匹配额外按住 Ctrl 的组合。
- 普通字母按逻辑键匹配；命名键按 Enter、Arrow 等语义匹配。反引号一类符号统一规范化，不依赖 Shift 后一定产生 `~`，主进程与 renderer 共用匹配规则。
- 非美式布局无法产生默认符号时，提供自定义录入；不用「逻辑键或物理位置任一匹配」同时触发，以免产生双重绑定。
- 禁止全应用裸字母、数字、空格和方向键；看板、列表和请求卡片里的局部键除外。第一版不增加全局 Vim 模式和连按前缀。
- 页面和终端使用明确的保留列表；不把所有 `Mod` 组合统一吞掉。终端的复制粘贴保持平台习惯，尤其不能用 `Ctrl+C` 代替复制。
- 禁用动作的键位若在当前内容有原生含义则透传；明确属于应用且无原生含义的入口，可以显示简短原因，例如「当前没有聊天」。
- 浏览器当前由 Agent 控制时，是否允许用户输入继续沿用现有策略；快捷键不得绕过会话所有权或站点授权。

## 可发现性与自定义

P0 提供可搜索的快捷键速查，从帮助入口、命令面板和非编辑区 `Mod+/` 打开；标出「当前可用」和生效区域。所有菜单、工具提示、分屏提示及输入框发送菜单从同一份定义生成按键文字。

P1 在设置增加「快捷键」页，支持按动作或按键搜索、录入替代键、清除绑定、单项恢复和全部恢复。录入时暂停其他应用动作。冲突提示列出动作及区域：互斥区域可复用；会同时生效的绑定必须显式解决，不能依赖监听器注册顺序。已知系统保留键禁止占用，无法检测的系统或窗口管理器冲突明确标为无法保证。

文件栏、终端栏和浏览器栏的开关明确包含在 P1 的基本自定义中，和其他应用动作使用同一个设置入口：

| 设置项 | 默认键位（macOS） | 可用操作 |
| --- | --- | --- |
| 显示 / 隐藏文件栏 | `⌘⇧E` | 修改、禁用、恢复默认 |
| 显示 / 隐藏终端栏 | `Ctrl+反引号` | 修改、禁用、恢复默认 |
| 显示 / 隐藏浏览器栏 | `Ctrl+Shift+反引号` | 修改、禁用、恢复默认 |

点击「修改」后按下新组合，校验通过即保存并生效，Esc 取消录入。冲突时显示占用动作和生效区域，保留原绑定；已知系统保留键和必须交给终端的控制键不能用于面板开关。用户无需编辑配置文件。

改键后，侧栏按钮、菜单、工具提示、速查、renderer 和浏览器 host 同步更新；新键在普通界面、终端和网页获得焦点时一致生效，旧键立即释放。禁用后，原键也从应用保留列表移除，面板仍可通过按钮和命令面板操作。恢复默认时同样检查冲突，不覆盖另一个动作的用户绑定。

绑定按当前设备和平台保存，重启后保留；不将 macOS 的物理 Control 或 Command 组合机械同步为其他平台的按键。

P2 可考虑每个动作多个绑定、导入导出、终端透传偏好和两段组合键。默认方案保持单次组合；不为未来可能增加的功能提前占键。

## 实现边界

快捷键是 desktop 客户端偏好，沿用 [preferences.ts](../packages/desktop/src/renderer/src/preferences.ts) 的本机存储边界，不放进 core 的任务或会话数据。

- 在 `desktop/src/shared` 定义稳定动作 ID、平台默认绑定、显示名、作用域、重复策略和嵌入内容保留标记。规范化和匹配为无 Electron / DOM 依赖的纯逻辑，供 main 与 renderer 共用。
- renderer 维护当前上下文、判断动作可用性并调用已有 store 操作；例如同配置新建复用 `newConversationFrom`，待处理复用 `actionableItems`。任务状态转换继续走既有规则。
- main 的浏览器 host 仅识别保留组合、阻止传给网页并把动作 ID 转发至所属窗口；不执行任务、git、会话或 Agent 逻辑。
- 自定义绑定通过 desktop IPC 同步到所属窗口的 host。以动作 ID 传递，不传入待执行代码。无需为本机按键偏好新增 core RPC；若实施时确需新 RPC，按仓库要求先定义协议。
- 注册当前可见界面的动作处理者，卸载时清理；处理时再读取当前活动会话，避免闭包把操作发给切换前的会话。
- 不为每个组件再写一套全局 keydown。CodeMirror、xterm 和网页保留局部键盘能力，通过上下文和少量应用保留键衔接。

## 兼容与迁移

任务创建、文件、分屏、终端和浏览器面板的主键位保持。行为变化单独在帮助和更新说明中列出：

| 原有行为 | 目标行为 |
| --- | --- |
| macOS 浏览器获得焦点后，面板开关修饰键不同 | 与应用界面统一为物理 Ctrl 组合；不保留有歧义的第二套默认键 |
| 网页 Esc 返回应用，Shift+Esc 才送给网页 | Esc 直接交给网页；用回到输入框的快捷键返回聊天 |
| 请求卡片的 Esc 可能停止或跳过 | 只退出请求焦点，拒绝、跳过和停止使用明确选项 |
| 空闲输入框的 `Mod+Enter` 不发送 | 空闲时发送，运行时仍按能力决定能否即时补充 |

可配置绑定采用带版本的本机格式。以后修改默认值只影响未覆盖的动作，用户的显式解绑也算覆盖；不能在升级时强制重置。旧动作 ID 更名时提供映射，已删除动作的覆盖保留为可解释的失效项。

## 实施优先级与验收

| 阶段 | 交付范围 | 完成标准 |
| --- | --- | --- |
| P0：统一基础与入口 | 收拢现有定义，修正浏览器开关键位差异；新增会话、快速切换、命令面板、回到输入框和速查；落地 Esc 消费规则 | 从聊天、文件、终端和网页都能用保留入口返回工作；已有主要键位保持；所有提示与实际绑定一致 |
| P1：管理多个 Agent | 最近访问、待处理导航、请求聚焦、布局入口、F6、基本自定义；浏览器查找 / 地址栏 / 标签快捷键 | 可仅用键盘依次找到等待项、读请求、回答、回到原工作；页面和终端的局部键不被串用 |
| P2：进阶配置 | 多绑定、导入导出、终端策略、按需支持组合键 | 自定义配置有版本与迁移规则；冲突能够解释和恢复 |

这些是建议的开发批次，不是本轮已经实现的功能。没有给出依赖尚未评估的工期。

关键验证场景：

1. 中文输入法组合和确认时，Enter 不发消息，N 不建任务，Esc 不停止 Agent。
2. 两列同时运行、同时等待时，查找、输入、聚焦请求和中断只影响前台目标；鼠标切换后立即生效。
3. 查找、候选菜单、弹窗和请求卡片上的一次 Esc 只退出一层，不连带中断、拒绝、跳过或返回看板。
4. 终端内 `Ctrl+C/K/N/P/J/W`、Esc 和 TUI 能照常使用；保留入口触发时不再向 PTY 发送额外字节。
5. macOS 浏览器获得焦点前后，终端和浏览器开关使用同一组物理 Ctrl 键；网页 Esc 正常，回到输入框不丢草稿。
6. 快速切换、最近访问和待处理导航正确处理删除、归档、群聊成员去重及当前目标已在另一列的情况；搜索慢响应不覆盖新查询。
7. 文件栏、终端栏和浏览器栏逐一验证改键、禁用、恢复默认与重启保留；main、renderer、菜单提示及速查同步更新，网页或终端聚焦时新键仍有效、旧键已释放。恢复默认遇到冲突不覆盖其他绑定；长按不会创建多个对象或重复提交。
8. macOS、Windows、Linux 分别验证默认绑定，并覆盖非美式布局、AltGraph 和符号键；系统保留键仍归系统。

实施涉及 desktop 时运行 `pnpm typecheck && pnpm test && pnpm build`，测试重点放在作用域仲裁、IME、事件消费、跨窗口转发与状态变化。手工试用使用 `ANTUMI_HOME=~/.antumi-demo pnpm dev`。本次面板快捷键设置的界面验证使用独立浏览器配置和不连接 core 的本地预览，未操作用户真实数据。

实际交付每一批可见行为时，再同步 README、使用指南与 `CHANGELOG.md` 的「未发布」。本轮不将规划写成已发布能力。
