# 新问题自动排查

在设置的来源页面，「同步到收件箱」下方打开「新问题自动排查」，选择项目、Agent、模型和每日上限后保存。首次开启只记录当前查询中的问题，后续首次进入结果的问题才会自动创建排查会话。这里的“新”表示首次发现，也包括后来被指派给自己、第一次进入查询的旧问题。

默认每个来源实例每天最多新增 10 个自动会话，按 core 所在机器的本地日期计数；全部来源同时主动排查一个问题。原文准备、首次启动、回复以及迟到图片的补充均占用此名额。等待用户补充信息或确认方案的会话让出自动名额，仍占用原有 Agent 进程名额。用户回复、批准或继续后视为接手，自动队列不再驱动该次排查。

自动启动使用 Agent 描述符的讨论模式，禁用绕过审批，来源原文仍作为不可信资料传入。自动阶段只接入只读 MCP 工具；不批准工具、不执行修复方案、不通过任务的无人值守预约启动，也不自动续跑被额度打断的会话。人工接手沿用原有会话操作。

## 发现与记录

core 的 `SourceInvestigationService` 接收 `SourceService` 成功同步的原始结果，不读取桌面端过滤后的列表。首次启用有成功结果就立即建立基线，否则等待第一次成功同步。已导入、已忽略和已有排查会话的问题同样记入已发现记录，但不进入自动队列。

配置、已发现编号及排查记录保存在现有 SQLite 数据库，与来源连接设置分开。一次事务写入新发现的编号和对应排队记录。来源身份包含 provider、instance、站点及账号绑定的摘要，不保存凭据原文；不同站点的相同编号分别处理。编号迁移时记录别名并再次查重。

普通重启保留基线。修改查询、重新登录、重新开启会重新建立基线；历史去重记录保留。关闭开关、关闭来源同步或更改查询会取消未开始的排队记录。项目、Agent、模型或补充说明的调整只影响未领取的记录；已领取记录保留原配置以供恢复。删除会话不会删除去重记录，也不会自动重建。

当前每个来源结果最多保留 200 条，达到上限会提示收窄查询；本功能不会扩展插件的分页或补抓历史数据。

## 调度与恢复

成功同步、会话状态变化和名额释放触发调度，另有一分钟兜底检查。来源实例轮转领取记录，遵守既有全局及单 Agent 进程上限。新会话创建后计入当日数量；重试原会话不重复计数。达到每日上限的记录留在队列，次日继续。

排查记录 ID 同时作为预分配会话 ID，来源与自动标记随会话首次插入一起落库。首条指令使用稳定引用 `auto-investigate:<记录ID>`。恢复先对账 daemon，再判断已有会话、准备状态及投递回执，不能仅凭内存是否存在来重新创建。原配置及补充说明跨重启保留；已提交正文的会话仅恢复未完成的图片下载，不重发首条指令。

准备阶段网络错误最多重试三次，间隔为 1、5、15 分钟。Agent 名额不足只等待，不消耗重试次数。配置、凭据或权限错误需修复对应原因。已提交的首条指令不自动重发；投递结果不明确的记录要求打开会话检查，保留启动日志和回执。对于可能还在执行的未确认投递，不开启下一条自动排查。

收件箱显示各条排查状态、今日数量及排队数量；来源设置和收件箱均可打开分页排查记录。安全可重试的失败记录提供重试，未开始的记录可以取消。失败记录或等待输入的会话沿用现有通知机制。

core 运行时不依赖桌面窗口。电脑休眠或 core 停止期间不执行，恢复后续跑。新能力标记为 `source-auto-investigation`；旧 core 不显示设置入口，旧客户端保存来源连接设置不会覆盖自动排查配置。
